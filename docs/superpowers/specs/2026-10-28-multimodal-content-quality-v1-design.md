# AIGC 多模态内容质量评估平台 V1 设计

## 1. 项目定位

将现有 `AI广告素材质量评估与优化系统` 升级为作品集级的
`AIGC 多模态内容质量评估平台`。V1 只覆盖同一广告生产链路中的三类内容：

- 广告视频；
- 广告图片；
- 广告脚本。

广告视频继续作为首个成熟场景。图片和脚本用于证明统一评估核心可以扩展到
不同内容类型，但 V1 不声称已经形成生产级通用平台。

## 2. 用户与问题

目标用户：

- AIGC 内容运营；
- Prompt 工程师；
- 广告素材审核人员；
- AI 应用产品人员。

V1 解决的问题：

- 审核标准分散且依赖个人经验；
- 模型内部状态和 JSON 不适合业务人员阅读；
- 视频、图片、脚本缺少统一的结果格式；
- 问题结论缺少可追溯证据；
- 输入或证据不足时，系统没有清晰的人工复核提示。

## 3. 已有能力

现有项目已经具备：

- FastAPI 视频上传；
- MP4/MOV 校验；
- FFmpeg/FFprobe 视频时长检测和关键帧提取；
- Agent 视频任务生命周期；
- 指定时间点补帧；
- Dify 固定工作流和受控 Agent 候选工作流；
- 最大步骤、补帧和重试限制；
- `completed`、`partial`、`human_review_required` 三种终态；
- 结构化证据和运行状态；
- 任务清理、上传限制和自动化测试。

现有候选 Agent 的最终报告直接展示 `state_json`，只能用于调试，不是业务报告。
现有固定工作流中已经存在人类可读 Markdown 模板，可作为报告结构参考。

## 4. V1 目标

V1 必须做到：

1. 视频、图片、脚本三类输入均能进入对应质检流程；
2. 三类流程返回统一的评估结果结构；
3. 用户默认看到人类可读报告，而不是内部 JSON；
4. 每个主要问题都能关联输入证据；
5. 输入不足、模型失败或低置信度时明确转人工复核；
6. 原有视频处理 API 和固定 Dify 工作流不被破坏；
7. 使用固定样本完成最小验证；
8. README 明确区分已完成能力和后续规划。

## 5. V1 不包含

- 漫画、MV、短剧等独立业务模板；
- 独立 React 管理后台；
- 用户、组织、角色和权限；
- 云端部署或公开发布；
- 批量任务和队列；
- 数据统计大屏；
- Promptfoo、DeepEval 或 Langfuse 的完整接入；
- 自动学习审核规则；
- 数据库 schema 变更或迁移；
- 生产级准确率和商业效果声明。

## 6. 统一概念模型

### 6.1 ContentAsset

表示待质检内容：

```json
{
  "asset_id": "uuid-or-workflow-id",
  "asset_type": "video | image | script",
  "scenario": "ad_content",
  "metadata": {}
}
```

### 6.2 QualityProfile

表示评估模板。V1 只提供三个固定模板：

- `ad_video_v1`；
- `ad_image_v1`；
- `ad_script_v1`。

V1 不提供用户自由编辑模板的管理界面。

### 6.3 Evidence

统一证据结构：

```json
{
  "source_type": "video_frame | image | text_span | user_input",
  "location": "00:03 | image:1 | paragraph:2 | field:target_audience",
  "dimension": "product_display",
  "finding": "商品主体被字幕遮挡",
  "confidence": 0.82
}
```

### 6.4 EvaluationResult

三类流程统一输出：

```json
{
  "asset_type": "video",
  "profile": "ad_video_v1",
  "status": "completed",
  "overall_score": 72,
  "summary": "核心卖点出现偏晚，CTA 不明确。",
  "dimension_scores": [],
  "issues": [],
  "strengths": [],
  "suggestions": [],
  "evidence": [],
  "missing_information": [],
  "human_review_required": false,
  "run_summary": {}
}
```

内部 Agent 状态继续保留，但不作为默认用户输出。

## 7. 三类评估模板

### 7.1 广告视频

评估：

- 前三秒钩子；
- 商品展示；
- 核心卖点；
- 目标人群匹配；
- 脚本/画面结构；
- CTA；
- 图文或脚本一致性；
- 缺失信息与人工复核要求。

证据定位使用视频时间点和关键帧。

### 7.2 广告图片

评估：

- 商品主体是否清晰；
- 视觉层级和构图；
- 文案可读性；
- 卖点与产品信息一致性；
- 目标人群匹配；
- CTA 或行动意图；
- 明显内容风险；
- 缺失信息与人工复核要求。

V1 的图片证据定位到图片编号和整体画面，不实现区域框选。

### 7.3 广告脚本

评估：

- 开场钩子；
- 用户痛点；
- 核心卖点；
- 目标人群匹配；
- 信息结构和节奏；
- CTA；
- 无依据的效果或数据宣称；
- 缺失信息与人工复核要求。

证据定位到段落或场次。

## 8. 用户流程

```text
选择内容类型
→ 上传视频/图片或粘贴脚本
→ 填写产品、受众、转化目标等上下文
→ 执行对应预处理与模型评估
→ 校验统一结构
→ 生成用户报告
→ 同时保留技术运行摘要
```

视频继续使用 FastAPI 进行上传、抽帧和补帧。图片由 Dify 文件输入进入视觉模型，
脚本使用文本输入。若 Dify/当前模型无法可靠传递图片，V1 必须保留证据并报告阻塞，
不得把纯文本调用称为图片质检成功。

## 9. 报告设计

### 9.1 默认用户报告

```markdown
# AIGC 内容质量评估报告

## 总体结论
- 内容类型
- 综合评分
- 运行状态
- 是否需要人工复核

## 关键问题
### P0/P1/P2
- 问题
- 证据
- 影响
- 修改建议

## 分项评分

## 内容优势

## 优化方案

## 缺失信息与人工复核提示
```

### 9.2 技术详情

单独输出：

- Agent 步骤数；
- 已执行动作；
- 是否补帧；
- 重试次数；
- 停止原因；
- 原始 `state_json`（仅调试输出）。

默认用户报告不得直接嵌入完整 `state_json`。

## 10. 实施方式

### 方案 A：只扩展当前 Dify DSL

最快，但统一数据结构容易散落在多个模型节点中，后续维护困难。

### 方案 B：Dify 编排 + 确定性统一结果转换（选定）

- Dify 负责内容类型分支和模型调用；
- 视频继续使用现有 FastAPI 工具；
- 各模型节点输出结构化结果；
- 确定性代码/模板节点将结果转换成统一结构和报告；
- 保留内部技术状态作为单独输出。

该方案能在三天范围内完成，同时保留后续接入评估框架和独立前端的空间。

### 方案 C：立即开发独立前后端平台

产品形态最好，但超出三天作品集 V1 范围，不采用。

## 10.1 实施决策补充

为避免实施阶段继续扩大范围，V1 固定采用以下决策：

- 新候选 DSL 从 `AI-Ad-QA-agent-v1.yml` 派生，因为视频仍需保留受控 Agent
  的决策、补帧和停止闭环；现有固定工作流的人类可读报告模板仅作为展示结构参考；
- 只有视频分支使用受控 Agent 循环；图片和脚本分支各使用一次结构化模型调用，
  不在 V1 中为三类内容各建一套 Agent；
- 使用一个统一 Dify Workflow，通过 `asset_type` 进入视频、图片或脚本分支；
- V1 使用当前 Dify 环境中已经配置且具备对应能力的模型。实施第一步先做最小图片
  视觉链路验证；若当前提供器不能传递图片，停止图片分支扩建并保留证据，不修改密钥
  或 `.env`，也不把纯文本调用称为图片质检成功；
- V1 必须完成至少一次真实 Dify 端到端调用，静态 DSL 测试和模拟数据不能单独作为
  三类内容已完成的证据；
- 验证样本默认使用程序生成或公开的非敏感素材。技术样本只证明链路，不证明真实
  广告判断质量；用户可在后续自行增加脱敏业务样本；
- V1 不新增数据库，历史记录、统计和团队协作留到后续版本。

## 10.2 统一结果子结构

`dimension_scores` 项：

```json
{
  "dimension": "hook",
  "label": "开场钩子",
  "score": 6,
  "max_score": 10,
  "status": "evaluated | partial | not_applicable",
  "reason": "开场呈现产品，但缺少明确结果或冲突。"
}
```

`issues` 项：

```json
{
  "priority": "P0 | P1 | P2",
  "dimension": "hook",
  "problem": "核心卖点出现过晚",
  "impact": "前三秒无法建立观看理由",
  "evidence_refs": ["evidence-1"],
  "suggestion": "在 00:02 前增加核心卖点。"
}
```

`suggestions` 项：

```json
{
  "priority": "P0",
  "action": "调整开场镜头",
  "expected_effect": "更早建立产品与用户需求的关联",
  "evidence_refs": ["evidence-1"]
}
```

`run_summary`：

```json
{
  "steps": 3,
  "completed_actions": ["analyze_frames", "check_ad_script"],
  "supplementary_frames_used": false,
  "retry_count": 0,
  "stop_reason": "sufficient_evidence"
}
```

综合分为所有 `evaluated` 分项的等权平均并换算为 100 分。`partial` 分项参与计算但
必须降低结果置信度；`not_applicable` 不参与。V1 不引入无法解释的模型自定义权重。

## 10.3 输入和人工复核规则

三类内容均必须提供待质检内容本身。产品信息为业务判断的最低上下文；未提供产品
信息时可以完成内容结构检查，但状态不得为完整可信结论。

- 目标受众、转化目标和补充要求为可选；缺失时写入 `missing_information`；
- 仅缺少可选字段时使用 `partial`，不自动转人工；
- 内容无法读取、结构化结果连续失败、核心证据相互冲突或整体置信度过低时使用
  `human_review_required`；
- 系统不得为缺失的产品功能、价格、效果、认证或业务数据生成事实。

## 11. 版本和文件策略

- 不修改 `workflow/current/AI-Ad-QA-current.yml`；
- 不覆盖 `workflow/candidate/AI-Ad-QA-agent-v1.yml`；
- 新候选 DSL 使用独立文件，例如
  `workflow/candidate/AIGC-Multimodal-QA-v1.yml`；
- 需要新增的测试放在 `tests/`；
- 产品定位、启动方式和已知边界同步更新 README；
- 不修改 `.env`、密钥、Docker 配置和系统设置；
- 不推送、不发布、不部署。

## 12. 三天作品集 V1 计划边界

### 第一天

- 建立统一结果结构；
- 修复候选 Agent 报告不可读问题；
- 分离用户报告与技术详情；
- 保持原视频接口兼容；
- 添加报告结构测试。

### 第二天

- 新增图片质检分支；
- 新增脚本质检分支；
- 统一三类结果；
- 添加输入不足、失败和人工复核路径。

### 第三天

- 准备固定样本；
- 运行自动化和完整链路验证；
- 修复阻塞问题；
- 更新 README；
- 整理演示步骤、项目边界和简历证据。

## 13. V1 验收标准

- 视频、图片、脚本分别有至少一个固定样本；
- 三类输入均输出同一顶层结构；
- 用户报告不显示原始 JSON；
- 每类报告至少包含总体结论、问题、证据、建议和人工复核提示；
- 视频问题能够引用时间点；
- 脚本问题能够引用段落/场次；
- 图片问题能够引用图片编号；
- 缺少必要上下文时不编造结论；
- 原有 `/api/v1/videos/extract` 和 Agent 视频任务 API 不被破坏；
- 项目自动化测试全部通过；
- README 明确标记为作品集 V1，不声称生产部署或商业效果。

## 14. 后续版本功能池

### V1.1：可用性完善

- 报告下载为 Markdown/PDF；
- 批量上传与任务进度；
- 评估失败后的局部重试；
- 更清晰的人工确认入口；
- 图片区域级证据；
- 视频问题对应关键帧预览。

### V1.2：评估和版本能力

- Prompt 版本管理；
- 不同模型横向对比；
- 固定测试集和回归评估；
- 人工评分与模型评分一致性统计；
- Promptfoo 或 DeepEval 接入；
- 成本、耗时、Token 和失败率记录。

### V2：产品化平台

- 独立 Web 界面；
- 历史任务与报告管理；
- 评估模板配置；
- 组织、用户和角色权限；
- 团队审核流；
- 问题标签和趋势统计；
- Langfuse 等可观测能力；
- 数据库存储和迁移方案（需单独批准）。

### V3：多业务场景

- 漫画分镜和角色一致性；
- MV 镜头与歌词/节奏一致性；
- 短剧剧本与镜头执行性；
- 商品详情页内容质检；
- 各场景独立测试集和评估模板；
- 场景模板市场或导入导出。

## 15. 作品集表达边界

V1 完成后可以表述：

> 基于 Dify、FastAPI 和多模态模型，设计并实现覆盖广告视频、图片和脚本的
> AIGC 内容质量评估 V1，统一问题、证据、评分和优化建议结构，并将 Agent
> 内部状态转换为业务人员可读报告。

在没有完成固定样本对照测试前，不写准确率、效率提升百分比或生产业务效果。
